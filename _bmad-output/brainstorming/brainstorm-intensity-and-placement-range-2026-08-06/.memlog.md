- (technique) started Parameter Matrix — decomposing 'intensity' into its underlying knobs
- (insight) Intensity is currently a closed 2-value enum (relaxed/intense) wired straight into LESSON_SIZE_BY_INTENSITY and COGNITIVE_LOAD_THRESHOLD_BASE — both are just lookup tables, so widening the enum is a bounded change, not a rearchitecture
- (idea) Add a Casual tier below Relaxed (~5 min, 2-3 items/day) for people who just want a trickle
- (idea) Add a Committed tier above Intense (~45-60 min) for cram/exam-prep users
- (idea) Replace fixed presets with a continuous slider (3-60 min) that snaps to sensible lesson-size buckets under the hood
- (idea) Keep 2-3 named presets as the default UI, add a Custom option that reveals a slider/stepper
- (idea) Split 'pace' into two independent controls: new items/day and reviews-per-day cap, since reviews already grow independently of intensity
- (idea) Ask time-based ('I have about __ min/day') and convert internally to item count via estimated seconds-per-item, derived from placement quiz response timing
- (idea) Offer intensity as item-count chips (3/5/10/15/20) instead of minutes, since minutes-per-item varies wildly by literacy
- (idea) Show 'why we recommend this' microcopy per option, computed from the placement quiz result (e.g. you knew 80% of N5 - Intense keeps pace)
- (idea) Expose weekly total load instead of daily minutes - '5 days a week intense' vs '7 days a week relaxed' can be the same weekly load
- (idea) Preview a computed date per pace option (N5 completion date), reusing the 'promise' framing from the onboarding-cards session
- (idea) Decouple study time-of-day from intensity - a separate 'when do you usually study' question feeds notification scheduling only
- (idea) Allow goal-ring seed and lesson size to be decoupled later in Settings for advanced users, instead of always moving together
- (idea) Flexible/adaptive mode: no fixed daily target, ask once per session roughly how much time is available today and size the lesson to that
- (idea) Re-offer the intensity choice after the first real lesson, now that it is informed by lived pace, not a guess
- (idea) Replace the binary with a 5-point scale: Light(3)/Relaxed(5)/Steady(7)/Intense(10)/Immersive(15)
- (idea) Cognitive-load-aware pacing: ask how heavy reviews should feel (light/moderate/heavy) and let new-item intake auto-tune to hit that review load in ~2 weeks, instead of fixing item count directly
- (idea) Import-aware default: seed the suggested intensity from the importer's historical pace (WaniKani/Anki review volume) instead of defaulting to Relaxed
- (idea) Make the existing lesson-preview banner drive a live continuous slider instead of discrete chips - 'today's lesson: N items' updates as you drag
- (idea) Reframe away from 'minutes' entirely toward 'how many new things a day', since reading speed makes minutes a false precision
- (idea) Advanced 2D picker: new-items/day on one axis, review tolerance on the other, collapsed by default behind the simple 3-chip preset
- (technique) started Constraint Relaxation on the placement quiz — questioning the single-level, binary-answer, ratio-cutoff design
- (insight) Current placement quiz is bounded to one JLPT level, asks a flat yes/no per item, and converts the ratio into a single curriculum-order cutoff per type - the 'range' the user can express is one number per type, inside one level
- (idea) Adaptive staircase: if the user is acing the sampled level (over ~80% known) pull in a harder-level batch mid-quiz instead of stopping at one level
- (idea) Symmetric down-staircase: if they are missing most of the sampled level, drop a level and test there too, so a wrong guess self-corrects without an all-or-nothing restart
- (idea) Let users pick their own level range up front with a two-handle slider over N5-N1 before the quiz starts, then stratify the sample across that whole span
- (idea) Run the staircase per item type independently - kanji and vocabulary knowledge often diverge, so one shared level shortchanges one or the other
- (idea) Replace binary Know-it/Not-yet with a 3-way confidence answer (Not at all / Kind of / Solid) that feeds a softer, half-weighted known ratio
- (idea) Offer an opt-in longer pass - 'answer 12 more for a more precise placement' - instead of a fixed sample size for everyone
- (idea) Add a manual-adjustment middle path on the summary screen: a browsable checklist of items near the computed boundary, instead of only accept-all or start-from-scratch
- (idea) Visualize the cutoff as a draggable handle over the curriculum's ordered item strip - turns an abstract ratio into something directly manipulable
- (idea) Bias resampling toward items near the current estimated cutoff (IRT-style adaptive item selection) so the fixed 12 questions concentrate where they are most informative
- (idea) Per-type retake: if one type's result looks wrong on the summary, let the user redo just that type's mini-quiz instead of the whole thing
- (idea) Import-first placement: when a WaniKani/Anki import exists, seed the quiz sample and prior from real import SRS data - the question becomes confirm/correct rather than guess-from-zero
- (idea) Let high-confidence self-raters skip the staircase and jump straight to a wide multi-level sweep (N5 through N2 in one pass)
- (idea) Add a first-click rough self-estimate (five-point bar) before the item quiz, so the 12-item sample centers near their guess instead of always starting at the flat default level
- (idea) Show the result as a range, not a point - 'placed between item 40 and 65 of 120' - with confirmation being a slider nudge inside that range rather than accepting one computed number
- (insight) SYNTHESIS 1 - Code check found a real bug-shaped gap behind the user's request: resolvePlacementKnownIds computes ONE ratio across ALL answers combined, then applies that single ratio to every type's cutoff. So today, acing radicals and bombing vocabulary still produces the same cutoff position for both - the quiz already samples per type but throws that signal away at the cutoff step
- (insight) SYNTHESIS 2 - Two different notions of 'range' surfaced: which levels get tested (currently locked to one JLPT level) and how precisely the cutoff within a level is set (currently one blended ratio, all-or-nothing accept). Both are worth solving, but the second is a small isolated fix, the first is a bigger multi-level sampling change
- (insight) SYNTHESIS 3 - Intensity and placement-range are the same underlying pattern: a single global knob standing in for what should be several independent, per-type or per-day signals
- (decision) CHOSEN - Intensity: widen relaxed/intense to a 5-step named scale (Light/Relaxed/Steady/Intense/Immersive), keep it as simple tap-chips (same ChoiceCard pattern), add recommend-from-placement microcopy, keep the existing re-offer-after-first-lesson idea from the prior session
- (decision) CHOSEN - Placement quick fix: make resolvePlacementKnownIds compute the known ratio per item type instead of one blended ratio across all answers - fixes the range problem the user is intuitively pointing at, no UI change required
- (decision) CHOSEN - Placement range control: two-handle level-range slider before the quiz (test N5 through N3 in one pass) plus a draggable cutoff handle on the result screen as the middle path between accept-all and start-from-scratch
- (decision) DEFERRED - adaptive per-question staircase and IRT-style resampling: real precision gains but a bigger lift than the quick fix and slider justify right now
- (decision by user) PRIORITY - build the range-slider approach first (level-range picker before the quiz + draggable cutoff handle on the result screen), not the per-type ratio quick fix
- (decision by user) SCOPE - fold the per-type ratio fix into the same story as the range-slider work, since both touch placementEngine.ts
