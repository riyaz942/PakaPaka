# Grammar content — linked words

**Date:** 2026-10-17
**Status:** Code done; in-app check pending
**Scope:** N5 + N4 grammar (161 points). Sub-project A of two; sub-project B (grammar mnemonics) gets its own spec.

---

## 1. Problem and intent

Everywhere except grammar content, Japanese words are linked: tap opens the word, long-press toggles its furigana, and furigana follows the word's own mastery (`LinkedSentence`, FR78). Grammar content does not do this:

- **Words do not link.** In the grammar lesson text (prose and ```` ```jp ```` blocks) a tap only shows or hides a reading. It never opens the word.
- **Furigana works per kanji, not per word.** The lesson text carries per-kanji brackets (`明日[あした]は早[はや]く起[お]きます`) with no word boundaries. `LessonMarkdown` makes each annotated run its own tap target, and 'auto' mode keys on `knownKanji` per character, not on word mastery.
- **"Uses" sentences do not link.** `GrammarUsesSection` renders each use sentence with a plain `FuriganaText`.

**Success:** on the grammar detail page and in the grammar lesson steps (overview, "How it works"), every taught word in the lesson text and in the "Uses" sentences behaves like a word in an example sentence: tap → detail page, long-press → that word's furigana, 'auto' furigana by that word's mastery.

**Constraints:** no model regeneration of lesson content; lesson `.md` sources unchanged; offline (no on-device tokenizer); `Result<T, AppError>` for fallible ops; no runtime writes to `curriculum.db`.

## 3. Marker format

Built JSON (`curriculum/grammar/n4.json`, `n5.json`):

```
{{<vocab-slug>|<inflection>|<annotated text>}}
```

Compiled `curriculum.db` (slug replaced by the vocabulary item id):

```
{{<item-id>|<inflection>|<annotated text>}}
```

- `<inflection>` is empty for a dictionary form, else one of `masu`, `te`, `nai`, `ta`, `stem`.
- `<annotated text>` keeps the existing bracket furigana (`起[お]きます`).
- Examples: `{{ashita||明日[あした]}}`, `{{okiru|masu|起[お]きます}}`, `{{hayai|stem|早[はや]く}}`.

`{{` and `}}` do not occur in the current lesson text (checked 2026-10-17); the build rejects a lesson that contains them, so a marker can never be confused with authored text.

## 4. Build — `curriculum/_build/generate.py`

In `_annotate_lesson_markdown` (the existing furigana pass), per ```` ```jp ```` line and per Japanese prose run outside inline code:

1. Derive spans on the **plain** text: `spans.derive_spans(text, known_vocab_forms)` merged with `spans.build_stem_spans(text, forms_by_slug)`.
2. Annotate the text with furigana exactly as today.
3. Map each plain span onto the annotated string (walk base characters, skipping `[reading]` groups). If a span edge falls inside a multi-kanji furigana group, drop that span and print a warning (D5).
4. Wrap each mapped span in a marker.

For each `uses[]` entry: `word_spans` = derived + stem spans over `use.japanese`, same candidate words.

Lesson `.md` files under `curriculum/grammar/lessons/` stay plain Japanese; authors never write markers.

---

## 5. Compile — `scripts/compile-curriculum.ts`

- Parse every marker in `explanation_markdown`. For each: the slug must resolve to a vocabulary item; the text with furigana stripped must equal `primary_form` (no inflection) or start with `inflection_stem(primary_form)` and differ from it (inflected / stem). This reuses the existing word-span check in `compile-curriculum.ts` by checking a one-span text per marker.
- Rewrite slug → vocabulary item id in the stored markdown.
- Any bad marker fails the compile, as a bad word span does today.
- `uses[].word_spans`: validated with the existing word-span check; stored in the `uses` JSON with item ids and the same `inflection` mapping (`stem` → null).
- `curriculum.schema.json` / `validate-schema.ts`: accept `word_spans` on a `uses` entry.
